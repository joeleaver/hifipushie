# Gates: four steps at every stage, the reference first

A piece can be clean and wrong. These four steps are what stands between "it runs" and "it is the thing in the
reference". They apply to every stage of every subject: a blockout, a face, a garment, a terrain.

1. **DESCRIBE**, before any work: what the reference shows at this stage, in words and as items you can measure
   (a proportion, a count, a position, a colour), each with the value read off the reference and a tolerance. Say
   which items you inferred because the reference does not show them. Nothing is chosen (a template, a default, a
   preset) until this exists, and the choice is argued from the items. `set_plan` and `set_reference` hold it for a
   model; a domain's first tool does it for that domain (find_tool names it).
2. **MEASURE**, every round: every item on the result, as a table: item | reference | ours | pass. The failed items
   are the fault list; fix the biggest first. A tool's own checks (`check`, a validator, a budget) are necessary,
   never enough.
3. **LOOK**, every round, with eyes that are not yours: `review_view`, ONE view per call: one region, the
   reference crop beside the result crop, no captions, no numbers, no claims. It lists faults MAJOR / MINOR and ends
   in a verdict. Fix every independent MAJOR you can (group them by cause first: one cause often explains several),
   then review the same regions again. A verdict you argue away needs evidence that the reference does not show it.
4. **APPROVE**: a person does this, never the author and never an agent on its own work. A stage consumes only
   approved pieces, so when your work is ready, say plainly what is waiting for approval and stop that piece there.
   Until a piece is approved, what is built on it is a draft.

What goes wrong without them: guide(topic="traps").
